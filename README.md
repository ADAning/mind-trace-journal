# 心迹 Mind Trace

> 一个以对话记录、个人状态观察和周期回顾为核心的 Obsidian 插件。

心迹希望把零散的感受整理成可以长期回看的个人轨迹：用几分钟完成一次引导式记录，在本地保存为 Markdown，并通过趋势、主题、周报和月报回看近期发生的变化。

当前版本为 **0.1.0**。

## 主要功能

- 统一主页面：主页、轨迹、记录（主操作）、回顾、观照五个模块在同一页面内切换，随时从任意页面开始记录。
- 引导式日记：从心情、精力和压力自评开始；评分后以“本次记录”上下文栏持续显示真实进度、三项状态和已保存回答，右侧用连续问答流生成日记。
- 结构化回顾：保留日记正文、事件图谱、智能切片、反思洞察、微行动和自我问题。
- 事件图谱：保存日记时提取事件事实、明确进展、主观体验、目标/意向与未决事项，并保留短原话、论元和明确关系；系统归纳与假设不会写入事实图谱。生成周报前以整个自然周、生成月报前以自然周片段统一校准，并分别写回每天。周报和月报记忆星图按照事件与实体的连接关系自动布局，选择节点后可核对日期、时间、进展、体验线索和原始上下文。
- 个人观测台：心情日历、上一周回顾、7/30/90 天状态趋势（心情/精力/压力独立成图，自评实线/AI 虚线）、主题、切片类别与最近事件。
- 历史与回望：在正文、事件、实体、主题、切片、反思和原始问答中进行本地全文检索，并按日期、主题与状态重新发现旧记录。
- 自动周期回顾：达到门槛后，为最近一个完整自然周生成周报；为最近一个完整自然月生成月报。回顾页可切换周报与月报，并支持本月截至今天的预览；周报/月报文件和内部报告 id 仍保留“报告”命名。
- 轨迹：默认打开“事件脉络”，沿日期、事件类型、行动与未决及跨事件实体线索回看事情如何发生；“日记与搜索”承接年度热力图、日记列表与本地检索。每张事件卡都可回到原日记并聚焦对应会话与事件。
- 观照：只基于最近 8 份周报与 3 份月报的分析字段，描出“最近的我”值得自行验证的变化；事实、归纳、假设分层展示，并支持逐条确认、修正、暂存或否认。
- 专用阅读页面：日记、周报和月报默认以统一的开放式证据文档展示；正文、证据、分析、主题和下一步沿细分隔线连续阅读，只有事件编辑器、交互图谱与折叠详情保留工具面板边界，同时保留原始 Markdown 编辑入口。
- 多模型支持：支持 OpenAI、Anthropic、Gemini、Kimi、DeepSeek、Qwen 和 OpenAI-compatible 服务。
- 隐私门：可选。可以为心迹页面设置本地密码锁，并在一段时间后自动锁定；也可以暂不设置，直接进入。
- 本地优先：日记和报告均保存在你的 Obsidian 仓库中，不依赖额外数据库。

## 安装

目前请通过 GitHub Release 手动安装：

1. 下载最新 Release 中的 `main.js`、`manifest.json` 和 `styles.css`。
2. 在 Obsidian 仓库中创建目录：

   ```text
   <你的仓库>/.obsidian/plugins/mind-trace-journal/
   ```

3. 将三个文件放入该目录。
4. 重新加载 Obsidian。
5. 在“设置 → 第三方插件”中启用“心迹”。

最低 Obsidian 版本为 **1.11.5**。

## 开始使用

1. 打开心迹设置，选择日记保存目录；如有需要，也可以分别指定周报和月报目录。
2. 选择模型服务并选择或填写模型名称；全新安装时若 Secret Storage 中已有密钥，默认选择名称排序第一的密钥并使用 Gemini（`gemini-3.1-flash`）。
3. 使用 Obsidian Secret Storage 选择 API Key。
4. 点击左侧功能区的心迹图标，进入心迹首页；页面内导航会在桌面顶部、移动端底部保持一致。
5. 选择日期并开始记录。

所有配置都会自动保存，插件重新加载后无需重复设置。

日记保存在设置的日记目录中。周报与月报目录留空时会跟随日记目录；也可以在 **设置 → 回顾与分析** 中分别填写独立目录。默认周报位置为：

```text
<日记目录>/报告/周报/YYYY-MM-DD--YYYY-MM-DD.md
```

默认月报位置（包含截至今天的部分预览与完整月报）为：

```text
<日记目录>/报告/月报/YYYY-MM.md
```

修改报告保存目录只影响后续报告的查找与保存位置；已有报告仍会保留在 Vault 中，并继续出现在回顾列表与观照来源中。

## 支持的模型服务

插件支持以下 LLM 服务商，所有服务商都在设置中提供模型选择；Kimi、DeepSeek 和 Qwen 提供常用模型预设，其余服务商可直接填写其支持的模型 ID。OpenAI-compatible 可用于 Ollama、vLLM、LM Studio 等本地或自建服务。

| 服务商 | 默认模型 | 可选预设 | 默认 Base URL |
| --- | --- | --- | --- |
| OpenAI | `gpt-5-mini` | 直接填写模型 ID | — |
| Anthropic | `claude-sonnet-4-5` | 直接填写模型 ID | — |
| Gemini | `gemini-3.1-flash` | 直接填写模型 ID | — |
| Kimi | `kimi-k2.6` | `kimi-k3`、`kimi-k2.6` | `https://api.moonshot.cn/v1` |
| DeepSeek | `deepseek-v4-flash` | `deepseek-v4-flash`、`deepseek-v4-pro` | `https://api.deepseek.com` |
| Qwen | `qwen3.7-plus` | `qwen3.8-max`、`qwen3.7-plus`、`qwen3.7-flash` | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| OpenAI-compatible | 需填写 | 直接填写模型 ID | `http://localhost:11434/v1` |

Base URL 都可以修改，以支持不同区域、云厂商专属地址或代理服务。插件不会自动切换模型或开启、关闭深度思考；需要使用其他模型或接口区域时，请直接修改模型 ID 或 Base URL。API Key 与所选服务商、区域必须匹配。

## 自动周报

- 只检查最近一个已经结束的周一至周日。
- 默认至少需要 4 个不同的记录日，可以在设置中调整为 4–7 天。
- 每周默认最多保留 50 件事件，记忆星图默认同时显示 20 件；两个上限都可以在设置中调整，完整事件始终保留在事件账中。
- 同一应用会话对同一周期最多自动尝试一次。
- 不会批量回溯历史周报，也不会自动覆盖已有报告。
- 手动生成尚未结束的本周版本时，文件名也使用完整的起止日期；文件内容通过 `period-status: partial` 标记为预览。
- 当源日记晚于报告更新时，会提示报告可能已经过期。
- 首页首屏按“日期与记录 → 三通道状态 → 心情日历与状态趋势”展开：桌面端日历最多占工作区三分之一，三张独立趋势图占其余空间；近期事件、回顾与观照位于下一层。回顾页顶部有“正在形成”进度条，周报与月报并排显示：普通进度使用靛蓝，超过门槛的部分使用带纹理的观照色并以门槛分隔线标示；月报按自然周分段计算，同时明确显示达成段数与溢出天数。

周报中的数值由本地日记计算。AI 负责整理文字观察，不应被视为心理或医学诊断。

轨迹只使用本地历史索引中的结构化事件。跨事件连续线索以同实体类型（kind）+ 规范化 name 的实体为键，并保留每件事件的类型、用户明确表达的进展、体验与方向线索、日期、时间和原始会话位置；它不会推断人格、因果关系或完成状态。“行动与未决”只是一个快捷筛选，不能自动判定未完成事项。没有结构化事件的记录会安静提示，并可切到“日记与搜索”，不会自动补写事件。打开事件时会保留原日记路径、会话序号与事件序号，方便核对原始经验。

## 轨迹与回顾的分工

- **轨迹**回答“事情如何发生、当时如何体验、还有什么在继续”：展示可核验的日期、时间、事件类型、明确进展、标题、摘要、用户自述体验、目标/未决线索、实体和明确关系，并提供事件脉带与原记录入口。
- **回顾**回答“这个周期可以怎样理解”：按自然周或自然月整理变化，保留生成进度、周期内统计、预览、归档、证据日期和模型流程。全局累计记录日、连续记录等概览只在轨迹顶部出现一次。
- 轨迹的事件脉络与日记搜索共用同一份本地 `historySnapshot`，筛选和分页不会重复读取 Vault；检索同时覆盖事件与实体。

日记叙述者本人统一使用人物实体“我”，不会抽取为“用户”。已有数据中名称精确为“用户”的人物节点会立即按“我”显示，并在下次保存事件或执行周级校准时写回规范名称；“插件用户”等具体群体名称不受影响。

周报生成或刷新前会把同一自然周内尚未人工确认的事件作为一个请求发送给当前模型，统一校准事件进展、体验/方向线索、论元、实体名称和明确关系后分别写回每天。实体名称会结合类型、角色、所属组织/项目、共同参与者、明确关系和相邻事件消歧：上下文能唯一对应时复用稳定名称，同名但上下文冲突时分开，上下文不足时不猜测。在事件编辑器中保存过的会话会标记为人工确认，之后不会被自动覆盖。写回前会检查日记是否在模型处理期间发生修改，检测到冲突时停止写回和周报生成。

## 自动月报与本月预览

- 自动月报只检查最近一个已经结束的自然月；每个 Obsidian 会话最多尝试一次，周报任务完成后才开始月报任务，不回溯历史月份。
- 完整月默认需要 4 个活跃自然周（每个周一至周日区间至少有一天记录），设置可调整为 1–5 周；本月预览只需至少 1 个记录日，并标记“截至今天”。回顾页月报的“正在形成”进度按本月覆盖的自然周分段，每段按周报最低记录日独立判定，达成段打勾。
- 部分预览与完整月报共用 `<日记目录>/报告/月报/YYYY-MM.md`。自动任务只创建缺失文件，不覆盖已有预览、过期报告或手工编辑内容。
- 月报 AI 摘录总预算为 24000 字符，先按活跃自然周平均分配，再按周内会话平均截取，尽量保证每个活跃周有输入。统计与事件覆盖整个周期；月度星图默认显示 100 件事件（可在 50–200 间以 10 为步长调整），完整事件保留在折叠事件账中。
- 月报 Markdown 固定包含本月概览、本月数字、月内节奏、本月事件图谱、发生的变化、可能的原因、AI 情绪假设、反复出现的主题、下月最小的一步和留给自己的问题。自然周节奏轴同时展示每周记录日、篇数、心情、精力与压力。

月报生成前会把月内会话按周一至周日分组，逐段调用模型校准；人工确认的事件不会覆盖。写回前会预检日记文件修改时间，发现冲突会停止任务并明确报告已写回与未写回的部分。

## 观照

“观照”不是画像，也不定义固定人格。它从最近可解析的周报/月报中回答“最近的我，出现了哪些值得我自己验证的变化？”，并保存一份可删除、可重新生成的本地快照：

- 来源按周期倒序汇集最近 8 份周报和 3 份月报；无法解析的报告会跳过，至少 1 份可解析报告才能生成。
- 观照证据日期只采用报告变化、可能原因或月内节奏中明确写出的日期；来源没有明确证据日期时不会用周期边界补造证据，生成会明确失败并提示补齐报告。
- 发送给模型的只有报告摘要、指标、变化、主题、情绪线索、下一步和自我问题，不发送原始日记。快照会记录来源报告路径、周期和生成时间，日期证据可以回到存在的日记或打开来源报告。
- 变化描线分为“单次差异 / 重复变化 / 稳定变化”。线索强度由本地证据日期计算：1 个日期为“初现线索”，2–3 个日期为“多次出现”，至少 4 个且跨度 ≥28 天才为“持续出现”；线索强度不等于真相概率。
- 事实、系统归纳与待验证假设明确分层。生活身份只作为有证据的“生活角色线索”，不会推断疾病、人格类型或受保护属性。
- 每条变化、视角、假设和角色都可“校准”：确认、否认或先保留，并可补充文字修正。否认会保留“你已否认”标签并在下一次生成时作为反馈，避免重复错误；删除观照只删除快照与反馈，不删除来源报告。

观照不会接入每日写作，也不会把未经确认的假设写回日记。初次观照可使用部分周期；跨周期和持续观照只计算互不重叠的完整周期，月报与其包含的周报不会重复增强线索。模型不可用、来源不足、解析失败和生成失败都会保留明确的下一步操作。

## 数据与隐私

- 日记、周报和分析来源文件保存在本地 Obsidian 仓库中。
- 生成个性化追问、日记或周报时，相关记录内容会发送到你主动配置的模型服务。
- 周级或月度事件校准只发送所选周期内的日记正文、切片、日级候选事件和人工保留事件，不发送原始问答；月报会按自然周片段分别发送。
- 心迹不会主动收集使用分析或遥测数据。
- 历史检索与回望推荐完全在本地执行，正文索引只保存在当前内存中，锁定心迹或退出 Obsidian 后即清除。
- API Key 通过 Obsidian Secret Storage 管理，不写入日记文件；插件不再读取系统环境变量。
- 密码锁用于保护心迹阅读界面，**不会加密磁盘上的 Markdown 文件**。需要磁盘级加密时，请使用操作系统或同步服务提供的加密能力。

使用第三方模型前，请同时阅读对应服务商的数据与隐私政策。
